# Vim Like

[![CI](https://github.com/onzuka24/vscode-extension-v/actions/workflows/ci.yml/badge.svg)](https://github.com/onzuka24/vscode-extension-v/actions/workflows/ci.yml)

VS Code 上で Vim ライクなモーダル編集を提供する拡張機能です。オペレータとモーションの
組み合わせ、カウント接頭辞、レジスタ、Visual モード、テキストオブジェクトに対応しています。

## 必要環境

- VS Code 1.85 以降
- ビルドとテストに Node.js 22.6 以降と npm

開発に使う Node のバージョンは [mise.toml](mise.toml) で固定しています。
[mise](https://mise.jdx.dev/) を使っている場合は `mise install` で同じ版が入ります。

## 導入と実行

```sh
git clone <repository-url>
cd vscode-extension-v
mise install   # mise を使わない場合は不要
npm install
npm run compile
```

VS Code でこのディレクトリを開き、`F5`（または「実行とデバッグ」ビューの **Run Extension**）を
実行すると、拡張機能が有効になった Extension Development Host が起動します。ビルドは
`.vscode/launch.json` の設定により自動で走ります。編集しながら試す場合は、別のターミナルで
`npm run watch` を実行しておくとインクリメンタルにビルドされます。

検査は `npm run lint`、`npm run typecheck`、`npm test`、`npm run package` で実行します。
GitHub Actions の CI でも同じものが、mise.toml で固定したものと同じ Node で走ります。

### VSIX を作って普段使いする

開発ホストを起動せずに常用したい場合は、VSIX を作って入れられます。

```sh
npm run package                                  # vscode-vim-like-0.1.0.vsix ができる
code --install-extension vscode-vim-like-0.1.0.vsix
```

拡張機能ビューの右上「…」→「VSIX からのインストール」からでも入れられます。
入れ替えるときは同じ手順で上書きされます。外すときは拡張機能ビューから
「Vim Like」をアンインストールしてください。

CI でも毎回 VSIX を作っています。GitHub Actions の実行結果から `vsix` という成果物を
落とせるので、手元でビルドせずに任意のコミットの版を試せます。

Marketplace への公開は行っていません。

#### 常用するときの注意

この拡張機能は VS Code 全体で1つしか登録できない `type` コマンドを使います。VSCode Neovim や
VSCodeVim と**同時には使えません**。どちらか一方を無効にしてください。競合していると、
起動時にどちらが原因かを名指ししたメッセージが出ます。

## 操作

### モード

| キー | 動作 |
| --- | --- |
| `i` `a` `I` `A` | Insert モードへ（現在位置 / 1つ右 / 行頭の非空白 / 行末） |
| `o` `O` | 下 / 上に行を開いて Insert モードへ。インデントを引き継ぎます |
| `v` `V` | Visual / Visual Line モードへ |
| `:` `/` `?` | コマンドライン・検索へ（下記） |
| `Esc` `Ctrl+[` | Normal モードへ |

Normal モードと Visual モードでは、割り当てのないキーはバッファに入力されず破棄されます。
`Backspace` `Enter` `Delete` のように `type` コマンドを通らないキーも、VS Code の編集動作が
そのまま働かないよう個別に受け止めています。

### モーション

`h` `j` `k` `l` `w` `W` `b` `B` `e` `E` `0` `^` `$` `gg` `G` `{` `}` `%` `f{char}` `F{char}` `t{char}` `T{char}`
`` `{mark} `` `'{mark}`

`Backspace` `Enter` `Delete` も Vim と同じくモーションです。`Backspace` は左へ（行をまたいで
戻ります）、`Enter` は次の行の先頭非空白へ動きます。`Delete` は `x` と同じで、カーソル位置の
1文字を消してレジスタに入れます。**いずれも VS Code 本来の編集動作（1文字削除・改行の挿入）は
起きません。**

いずれもカウント接頭辞を取ります（`3w`、`5j`、`2f,` など）。`G` はカウントで行番号指定になります。

`%` は対応する括弧へ移動します。カーソルが括弧の上になければ、その行を右に見ていって最初の
括弧を使います。対象は Vim の既定と同じ `()` `[]` `{}` の3種です。inclusive なモーションなので、
`d%` は括弧を含めて消します（モーションはカーソルから働くので、括弧の手前から打つとそこまでが
範囲に入ります）。

### オペレータ

`d` `c` `y` `>` `<` `gu` `gU` `g~` を上記のモーションと自由に組み合わせられます
（`dw` `d$` `c3w` `y}` `dfx` `>j` `gUiw` など）。オペレータを重ねると行単位になります
（`dd` `cc` `yy` `>>` `<<` `guu` `gUU` `g~~`）。カウントは前後どちらにも置け、
両方あれば掛け算されます（`2d3w` は6単語削除）。

短縮形として `D`（`d$`）、`C`（`c$`）、`Y`（`yy`）、`S`（`cc`）、`x` `X` `s` があります。

`>` `<` は行の字下げです。Vim と同じくモーションが文字単位でも行に作用し（`>w` は単語ではなく
その行を下げます）、下げ幅とタブ・スペースの別は VS Code の設定に従います。字下げ自体を
`editor.action.indentLines` に委ねているため、言語ごとの設定もそのまま効きます。

**カウントの意味がモードで変わります。** Normal モードは行数（`3>>` は3行を1段）、Visual モードは
段数（`3>` は選択範囲を3段）です。Vim / Neovim がそう決めているためで、Normal モードに段数を
指定する手段はありません。3段下げたいときは Visual モードで `3<` と打ちます（`<` は1つ。
`3<<` と打つと余分な `<` がオペレータとして保留になります）。

なお、それ以上下げられない行では何も起きません。インデントが1段しかない行に `3<` を打つと
1段だけ動きます（VS Code の字下げコマンドの挙動です）。

`gu` `gU` `g~` は大文字小文字を変えます（小文字に / 大文字に / 反転）。`gUiw` で単語を大文字、
`guu` で行を小文字、`g~$` で行末までを反転です。Vim と同じく `gugu` という綴りも受け付けます。
レジスタには触らず、終わったあとは Normal モードです。

Visual モードでは選択範囲に対して `u` `U` `~` の1打鍵で同じことができます（`gu` `gU` `g~` も
使えます）。Normal モードの `u` は取り消しのままです。

**カーソルの着地点が Normal と Visual で違います。** 行単位のとき、`guu` は行の先頭非空白に、
`Vu` は列0に着きます。Vim 9.1 の実挙動に合わせたもので、こちらで決めた差ではありません。

### テキストオブジェクト

`iw` `aw` `iW` `aW`、括弧の `i(` `a(` `i[` `a[` `i{` `a{` `i<` `a<`（`ib` `ab` `iB` `aB` も可）、
引用符の `i"` `a"` `i'` `a'` `` i` `` `` a` ``。オペレータの後（`ciw`）でも Visual モード中
（`viw`）でも同じように使えます。

### マーク

- `m{a-z}` で現在位置を覚え、`` `{a-z} `` でその位置へ、`'{a-z}` でその行の先頭非空白へ戻ります。
- どちらもモーションなので、オペレータと組み合わせられます。`` d`a `` は文字単位、`d'a` は行単位です。
- `G` `gg` `{` `}` `%` `/` `n` のような大きな移動は戻り先を覚えます。`` `` `` で直前の位置へ、
  `''` でその行へ戻れます。`h` `j` `k` `l` のような小さな移動は戻り先を書き換えません。
- マークはファイルごとに別々です。ファイルをまたぐマーク（大文字 `A-Z`）は未対応です。
- マークを付けた行は、行番号の横にマーク名が出ます（`vimLike.showMarks` で消せます）。
  出るのは `m` で付けた名前付きマークだけです。`` `` `` の戻り先は移動のたびに変わるため出しません。
- `:marks` で一覧が出ます。マーク名・行番号・その行の中身が並び、選ぶとその位置へ移動します。
  ガターと違い、こちらには `` `` `` の戻り先も載ります。どこから飛んできたかは一覧では有用だからです。
- `:delmarks a`、`:delmarks a b`、`:delmarks ab`、`:delmarks a-d` で消せます。
  `:delmarks!` は名前付きマークをすべて消します。Vim と同じく `:delmarks` は引数が必須です。
  `` `` `` の戻り先は `:delmarks!` でも残ります。移動のたびに付け直されるもので、消しても
  すぐ元に戻るからです。

### レジスタとその他

- `"a` などで名前付きレジスタを指定します（`"ayy` `"ap`）。大文字は追記です。
- `p` `P` で貼り付け。行単位のレジスタは行として、文字単位のレジスタは文字として貼られます。
- `r{char}` 置換、`~` 大小反転（Normal モードではカーソル位置から1文字ずつ）、`J` 行連結、
  `u` / `Ctrl+r` で取り消し・やり直し。
- `.` で直前の**変更**を繰り返します。カーソル移動やヤンクは変更ではないので、間に挟んでも
  繰り返す対象は変わりません（`cw` で直して `n.` `n.` と進む使い方ができます）。Insert モードを
  通った変更では、打った内容ごと繰り返します。`3.` は Vim と同じくカウントの置き換えで、
  「3回繰り返す」ではなく「元のコマンドをカウント3で実行し直す」意味です。

### コマンドライン（`:`）

`:` でコマンドラインモードに入ります。打った内容はステータスバーに `:w` のように出て、
フォーカスはエディターに残ります。`Enter` で実行、`Esc` で取り消し、`Backspace` で1文字削除
（`:` まで消すとモードを抜けます）。

| コマンド | 動作 |
| --- | --- |
| `:w` | 保存 |
| `:q` / `:q!` | 閉じる / 変更を捨てて閉じる |
| `:qa` / `:qa!` | すべて閉じる |
| `:wqa` `:xa` | すべて保存して閉じる |
| `:wq` `:x` | 保存して閉じる |
| `:sp` / `:vs` | 上下 / 左右に分割 |
| `:tabnew` | 新しいファイル |
| `:42` / `:$` | その行 / 最終行へ |
| `:marks` | マークの一覧。選ぶとその位置へ移動します |
| `:delmarks {名前}` | 指定したマークを消す（`a`、`a b`、`ab`、`a-d`） |
| `:delmarks!` | 名前付きマークをすべて消す |

#### `:` に自分の名前を足す

`vimLike.exCommands` で、`:` から呼べる名前を増やせます。値は実行する VS Code のコマンド ID です。

```jsonc
"vimLike.exCommands": {
  "gg": ["git-graph.view"],
  "blame": ["gitlens.toggleFileBlame"]
}
```

**他の拡張機能のコマンドはここに書きます。** この拡張機能の組み込みの表には、同梱していない
ツールのコマンド ID を入れません。入れ始めると利用者ごとの好みで際限なく増えますし、
その拡張機能が入っていない環境では動かないものが並ぶことになります。

複数並べれば順に実行されます。`:w` などの組み込みの名前は上書きできません（取り違えて
保存できなくなるほうが困るためです）。名前が使えない綴りだったり、コマンドの指定が
空だったりする項目は、理由を添えて知らせたうえで無効になります。

`:write` `:split` `:vsplit` のように省略しない綴りでも書けます。範囲指定や引数は解釈しないので、
`:w foo` や `:%s/a/b/` は `E492: Not an editor command` として知らせます。黙って別のことを
するよりは、できないと言うほうを選んでいます。唯一の例外が `:delmarks` で、こちらはマーク名を
引数に取ります（詳しくは[マーク](#マーク)を参照）。

保存の手段が `:w` だけというわけではありません。キー割り当てから VS Code のコマンドを直接
呼べるので、`{ "before": ["<leader>", "s"], "commands": ["workbench.action.files.save"] }` でも
同じです。init.vim の書き方に寄せたい場合は `{ "after": [":", "w", "<CR>"] }` と書けます。

### 検索（`/` `?` `n` `N` `*` `#`）

`/` で前方、`?` で後方に検索します。入力欄は `:` と同じくステータスバーで、`Enter` で確定、
`Esc` で取り消しです。確定するまでカーソルは動きません。

| キー | 動作 |
| --- | --- |
| `/pattern` `?pattern` | 前方 / 後方へ検索 |
| `n` `N` | 同じ向き / 逆向きに繰り返し |
| `*` `#` | カーソル下の単語を前方 / 後方へ検索 |
| `/` `?` を空のまま確定 | 直前のパターンをもう一度 |

バッファの端まで行くと反対側へ回り込みます（Vim の `wrapscan` 相当）。カウントは何個目の一致かを
指し（`3n`）、`d/foo<CR>` `dn` `v/foo<CR>` のようにオペレータや Visual モードとも組み合わせられます。

`n` の向きは**最後に打った `/` か `?` で決まります**。`?foo` のあとの `n` は後方へ続き、`N` が
前方へ戻ります。`*` `#` も同じく、直前の検索としてパターンを残します。

#### パターンは JavaScript の正規表現

Vim の方言（`\v` `\<` `\{-}`）は解釈しません。中途半端に翻訳すると、意図と違うものに黙って
一致するほうが厄介だからです。よく使うものの対応は次のとおりです。

| Vim | この拡張機能 |
| --- | --- |
| `\<foo\>` | `\bfoo\b` |
| `\d` `\s` | `\d` `\s`（同じ） |
| `\{-}`（最短一致） | `*?` `+?` |
| `\(...\)` | `(...)` |
| `\|` | `\|`（グループ内では `|`） |

大文字小文字は常に区別します（`ignorecase` 相当の設定はありません）。見つからないときや壊れた
パターンのときは、Vim と同じ文言（`E486: Pattern not found` など）をステータスバーに出します。

#### VS Code の検索バーも使う

`/` と `?` は常にこの拡張機能の検索です。VS Code の検索バーは `Cmd+F`（VS Code 既定）で開き、
`examples/settings.jsonc` では `<leader>/` にも割り当てています。

```jsonc
{ "before": ["<leader>", "/"], "commands": ["actions.find"] }
```

どちらか一方を選ぶ設定にはしていません。オペレータと組み合わせられるのは前者だけ、履歴と
一致件数があるのは後者だけで、優劣ではなく用途が違うためです。両方を別のキーに置いておけば、
そのとき欲しいほうを打てます。

| | `/` `?`（この拡張機能） | `Cmd+F` / `<leader>/`（VS Code） |
| --- | --- | --- |
| 入力欄 | ステータスバーに `/foo` | VS Code の検索バー |
| パターン | JavaScript の正規表現で固定 | リテラル / 正規表現をトグル |
| 大文字小文字・単語単位 | 常に区別 / `*` `#` のみ単語単位 | 検索バーのトグルで切り替え |
| 件数・履歴・ハイライト | なし | あり（「1/8」の表示、履歴、全一致の強調） |
| `n` `N` | モーション。`3n` も `dn` も効く | 検索バーの Enter / `Cmd+G` |
| `d/foo<CR>` `v/foo<CR>` | 効く | 不可（打鍵が検索バーへ行くため） |

Visual モードの `<leader>/` は `actions.findWithSelection` で、選択した文字列が検索語に入った
状態で開きます。`actions.find` でも既定では同じですが、そちらは
`editor.find.seedSearchStringFromSelection` の設定に左右されます。

なお `?` は Vim どおり後方検索のままです。US 配列では `Shift+/` が `?` そのものなので、
そこに検索バーを置くと後方検索が失われます。`<leader>/` を使っているのはこのためです。

init.vim で `<leader>/` にあったコメントのトグルは `<leader>c` に移しました（`Cmd+/` も
VS Code 既定のまま効きます）。オペレータの `c` は `c` のままです。

### ウィンドウ操作

`Ctrl+W` に続けて `h` `j` `k` `l` でエディターグループ間を移動、`s` `v` で分割、`c` で閉じます。

サイドバーやパネルの表示切替は VS Code 標準のキー（`Ctrl+B` など）をそのまま使います。
この拡張機能では再定義していません。

### AI パネルへ送る（`<leader>e` `<leader>E`）

現在行、または Visual モードの選択範囲を、開いている AI パネルへ送ります。送り先は
`vimLike.aiPanels` に書きます。

```jsonc
"vimLike.aiPanels": [
  { "name": "Claude Code", "command": "claude-vscode.focus" },
  { "name": "Codex",       "command": "chatgpt.addToThread" }
]
```

- `<leader>e` は先頭の送り先へ送ります。
- `<leader>E` は送り先を選んでから送ります。選んだ相手は、そのセッションのあいだ `<leader>e` の
  行き先としても残ります（設定には書き込みません）。
- 空行では何も送りません。

**送られるのは本文ではなく参照です。** `@src/core/engine.ts#512-540` のような、ファイルと行範囲を
指すものが相手の入力欄に入り、指示そのものは自分で打ちます。

これは手抜きではなく、**開いている会話に届けられるのがこれだけ**だからです。他の拡張機能が
公開している AI パネルのコマンドは引数を取らず、自分で `editor.selection` を読んで参照を作ります。
そこでこの拡張機能は、選択範囲を目的の行に合わせてからそのコマンドを呼び、終わったら選択を元に
戻します。任意のテキストを渡す道もありますが、それは**毎回新しい会話を開く**形にしかならず
（Claude Code は既存セッションに prompt を渡すと "Your prompt was not applied" と出して捨てます）、
「開いているパネルに送る」とは別のものです。

参照のほうが貼り付けより正確でもあります。相手はその場でファイルを読むので、送ったあとに
編集しても食い違いません。

相手のコマンド ID をこの拡張機能の側に持たないのは `:` の追加名と同じ理由です。同梱していない
ツールの ID を知っているべきではなく、組み込みの一覧は新しいアシスタントが出るたびに増えます。

## 設定

設定画面で `Vim Like` を検索してください。

- `vimLike.enabled`: Vim モードの有効・無効（既定値: `true`）。ステータスバーの表示をクリックしても切り替わります。
- `vimLike.startInNormalMode`: エディターを切り替えたときに Normal モードへ戻すか（既定値: `true`）
- `vimLike.showModeInStatusBar`: ステータスバーに現在のモードを表示するか（既定値: `true`）
- `vimLike.showMarks`: マークを付けた行の行番号の横にマーク名を表示するか（既定値: `true`）
- `vimLike.leader`: キー割り当ての `<leader>` が指すキー（既定値: スペース）
- `vimLike.aiPanels`: `<leader>e` `<leader>E` の送り先（既定値: 空）
- `vimLike.exCommands`: `:` で使える自分の名前（既定値: 空）

### キーの割り当てを変える

`vimLike.normalModeKeyBindings` と `vimLike.visualModeKeyBindings` で、キーを別のキー列に
置き換えられます。Vim の `nnoremap` / `vnoremap` に相当します。

```jsonc
"vimLike.normalModeKeyBindings": [
  { "before": ["H"], "after": ["^"] },
  { "before": ["J"], "after": ["1", "0", "j"] },
  { "before": ["K"], "after": ["1", "0", "k"] },
  { "before": ["L"], "after": ["$"] },
  { "before": ["U"], "after": ["<C-r>"] },

  { "before": ["<leader>", "n"], "commands": ["workbench.view.explorer"] },
  { "before": ["<leader>", "h"], "commands": ["workbench.action.navigateLeft"] },
  { "before": ["<leader>", "w", "h"], "commands": ["workbench.action.decreaseViewWidth"] }
]
```

- `before` と `after` は 1 要素が 1 キーです。`10j` は `["1", "0", "j"]` と書きます。
- `after` の代わりに `commands` を書くと、VS Code のコマンドを直接呼べます。
- `<Esc>` `<C-r>` `<Space>` `<leader>` が特殊キーとして使えます。
  `<leader>` が何を指すかは `vimLike.leader` で変えられます（既定値はスペース）。
- 置き換えた結果はさらに置き換えられません（`nnoremap` と同じく非再帰です）。
- `f` `t` `r` `m` `` ` `` `'` の引数と、`"` に続くレジスタ名は置き換えの対象外です。
  `J` を割り当てていても `fJ` は文字 `J` を探し、`` `J `` は名前 `J` のマークを指します。
- 複数キーの `before` は、より長い規則が一致しうるあいだ次のキーを待ちます。
  `["g", "w"]` と `["g", "w", "h"]` を両方定義すると、短いほうは発火しません。
  待機中はステータスバーに打鍵済みのキーが出ます（スペースは `␣` と表示されます）。
- Vim の `timeoutlen` にあたる打ち切りはありません。待っているあいだは表示で分かるので、
  手が止まっただけで打鍵が実行されるより確実だと考えています。

すぐ使える設定例を [examples/settings.jsonc](examples/settings.jsonc) に置いています。
`H` `J` `K` `L` の置き換えから leader 起点のウィンドウ操作まで一式入っているので、
settings.json に貼り付けてから削っていくのが早いと思います。

### エクスプローラーとターミナル

**エクスプローラーではモードやオペレータは使えません。** ツリービューであってテキスト
エディターではないため、打鍵が `type` コマンドを通らないからです。ただし `j` `k` `h` `l`
での移動なら、VS Code の `list.*` コマンドをキーに割り当てることで実現できます。
例を [examples/keybindings.jsonc](examples/keybindings.jsonc) に置いています
（settings.json ではなく keybindings.json に書きます）。

**ターミナルではモードやオペレータは使えません。** VS Code のターミナルに打たれたキーを
拡張機能が横取りする API がないためです（送り込む `sendText` と、シェル統合でコマンド出力を
読む API はあります）。行編集を Vim 風にしたい場合は、シェル側で `set -o vi`（bash）や
`bindkey -v`（zsh）を設定してください。

拡張機能が自前で用意する `Pseudoterminal` なら打鍵を受け取れますが、その場合はシェルの起動から
スクロールバックの管理まで全部を自前で持つことになります。採らない判断をした経緯は
[#31](https://github.com/onzuka24/vscode-extension-v/issues/31) にあります。

#### ターミナル用の作業バッファ

**Vim Like: Open Last Terminal Output** で作業バッファを開きます。ここにコマンドを書いて
**Vim Like: Send Line or Selection to Terminal** で送ると、ターミナルで実行され、出力が同じ
バッファに追記されます。

```jsonc
{ "before": ["<leader>", "t"], "commands": ["vimLike.openTerminalOutput"] },
{ "before": ["<leader>", "r"], "commands": ["vimLike.sendToTerminal"] }
```

```
npm run lint
─── $ npm run lint
all good
```

**文書なので Vim の機能がそのまま全部使えます** — 長いオプション付きのコマンドを `ciw` で
直して送り直す、検索でエラー箇所へ飛ぶ、`y` で必要な行だけ取る、マークで行き来する。
ターミナルの中に Vim を作るのではなく、作業ごと Vim が扱える場所へ持ってくる形です。

- 送ったあともフォーカスはバッファに残ります。ターミナルは裏で表示されるだけなので、
  続けて次のコマンドを書けます。対話的なコマンド（確認を聞くもの）を打つときは、
  ターミナルへ移ってから操作してください。
- 送り先のターミナルは1つを使い回します。開いているものがあればそれを、なければ作ります。
  新しく作った直後はシェル統合の起動を待ってから送るので、最初の1回も取りこぼしません。
- 選択範囲があればそれを、なければ現在行を送ります。
- 色などのエスケープは取り除き、進捗表示の `\r` による上書きも解決してから追記します。
- 実体は OS の一時ディレクトリ内のファイルです。閉じるときに保存を聞かれず、
  セッションの作業ログが1枚に残ります。プロジェクトごとに別のファイルになります。
- 出力が非常に長いときは末尾を残します。失敗の理由は終わりのほうにあることが多いためです。

##### シェル統合について

出力の取り込みには VS Code の**シェル統合**が要ります。シェルの起動時に目印を仕込んで、
コマンドの開始と終了を VS Code が識別できるようにする仕組みです。

- 対応シェルは **bash / zsh / fish / PowerShell** で、既定で自動的に有効になります。
- **効いているかはターミナルの左端の丸い印で分かります**（成功は青、失敗は赤）。
- `ssh` で入った先のシェルや対応外のシェルでは効きません。他の拡張機能が自前で作った
  ターミナルも対象外です。
- ターミナルを開いた直後は統合の起動が間に合わず、**最初の1回を取りこぼすことがあります**。

シェル統合がなくてもバッファを開くことと送ることはできます。追記されないだけです。
その状態で送ると一度だけお知らせが出ます。**Vim Like: Show Log** で、どこまで進んだかが見られます。

##### シェル統合が有効にならない場合

`echo $VSCODE_SHELL_INTEGRATION` が空なら有効になっていません。設定を確認しても原因が
見つからないときは、**シェルを自前のラッパーで置き換える種類のツール**を疑ってください。
`kiro-cli`、Amazon Q、Fig などが該当します。

これらは `.zshrc` の先頭で `exec` によりシェルプロセスを別物に差し替えます。VS Code の
シェル統合は `ZDOTDIR` を差し替えて自前の設定ファイルを読ませる方式なので、`exec` の時点で
仕込みごと消えてしまい、原理的に両立しません。

VS Code のターミナルでだけラッパーの起動を抑える方法があります。`kiro-cli` の場合は
起動条件に `PROCESS_LAUNCHED_BY_Q` の判定があるので、これを立てておけば `exec` を回避できます。

```jsonc
// settings.json
"terminal.integrated.env.osx": { "PROCESS_LAUNCHED_BY_Q": "1" }
```

引き換えに、VS Code のターミナルではそのツールの補完や提案が効かなくなります。他の
ターミナルアプリには影響しません。手動でシェル統合を導入する方法もあります。

```sh
# .zshrc の末尾（ラッパーの起動より後）に置く
[[ "$TERM_PROGRAM" == "vscode" ]] && . "$(code --locate-shell-integration-path zsh)"
```

なおこの拡張機能は、エクスプローラーやターミナルにフォーカスがあるときにキーを奪いません。
すべてのキーバインドに `editorTextFocus` を付けており、構造テストで強制しています。

## 制限

- `/` の検索には結果のハイライト（`hlsearch`）と入力中の追従（`incsearch`）がありません。カーソルが
  移動するだけです。どちらも欲しいときは `<leader>/` で VS Code の検索バーを開いてください。
  代わりにオペレータとの組み合わせ（`d/foo`）はできなくなります。
- 検索パターンは JavaScript の正規表現で、Vim の方言は解釈しません。
- `gu` `gU` `g~` は、大文字小文字の変換で文字数が変わる文字をそのまま残します。ドイツ語の `ß` は
  JavaScript では `SS`（2文字）になり、それでは以降の列がずれるためです。Vim は単一の `ẞ` に
  変えるので、どちらとも違う結果になります。
- Ex コマンドは決め打ちの一覧のみです。範囲指定や置換（`:%s/foo/bar/`）、引数（`:w foo`）は
  未対応です（例外は `:delmarks` のマーク名だけ）。
- `:qa!` は `:qa` と同じ動きで、未保存のファイルがあれば VS Code が確認を出します。
  すべてのエディターの変更を破棄して閉じるコマンドが VS Code に存在しないためです。
  1つ分の `:q!` は破棄できます。
- マクロは未対応です。
- マークは編集に追従しません。マークを付けたあとに上の行を消すと、マークは行番号のまま残るため
  指す場所がずれます。追従させるには文書の変更を購読して位置を補正する必要があり、まだ入れていません。
- `{count}%`（ファイルの何割の位置へ飛ぶ Vim の機能）は未対応です。`%` は括弧の対応のみです。
- `%` は `matchit` が足す `if`/`endif` や HTML タグの対応までは見ません。
- `.` は Insert 中にマウスや矢印キーでカーソルを動かすと、打った内容を記録できません。
  その場合は変更の構造だけ（`cw` なら単語の削除まで）を繰り返します。
- `u` と `Ctrl+r` は VS Code の取り消し履歴に委譲しているため、取り消しの粒度は Vim と一致しません。
- モードはウィンドウ全体で1つです。エディターごとに別々のモードは持ちません。
- マウス操作そのものは無効にできません（Vim の `set mouse=` に相当するものがありません）。
  クリックやドラッグは VS Code が直接扱うためです。ただし Normal / Visual モードで行末より
  後ろにキャレットが立った場合は、Vim の規則どおり最後の文字へ引き戻します。
- ドラッグ選択では Visual モードに入りません（Vim の `mouse=a` 相当）。VS Code の選択がそのまま
  残ります。
