# Vim Like

[![CI](https://github.com/onzuka24/vscode-extension-v/actions/workflows/ci.yml/badge.svg)](https://github.com/onzuka24/vscode-extension-v/actions/workflows/ci.yml)

VS Code 上で Vim ライクなモーダル編集を提供する拡張機能です。オペレータとモーションの
組み合わせ、カウント接頭辞、レジスタ、Visual モード、テキストオブジェクトに対応しています。

## 必要環境

- VS Code 1.85 以降
- ビルドとテストに Node.js 22.6 以降と npm

開発に使う Node のバージョンは [mise.toml](mise.toml) で固定しています。
[mise](https://mise.jdx.dev/) を使っている場合は `mise install` で同じ版が入ります。

## 導入と実行

```sh
git clone <repository-url>
cd vscode-extension-v
mise install   # mise を使わない場合は不要
npm install
npm run compile
```

VS Code でこのディレクトリを開き、`F5`（または「実行とデバッグ」ビューの **Run Extension**）を
実行すると、拡張機能が有効になった Extension Development Host が起動します。ビルドは
`.vscode/launch.json` の設定により自動で走ります。編集しながら試す場合は、別のターミナルで
`npm run watch` を実行しておくとインクリメンタルにビルドされます。

検査は `npm run lint`、`npm run typecheck`、`npm test` で実行します。GitHub Actions の CI でも
同じ3つが、mise.toml で固定したものと同じ Node で走ります。

現時点では Marketplace への公開や VSIX の配布は行っていません。

## 操作

### モード

| キー | 動作 |
| --- | --- |
| `i` `a` `I` `A` | Insert モードへ（現在位置 / 1つ右 / 行頭の非空白 / 行末） |
| `o` `O` | 下 / 上に行を開いて Insert モードへ。インデントを引き継ぎます |
| `v` `V` | Visual / Visual Line モードへ |
| `:` `/` `?` | コマンドライン・検索へ（下記） |
| `Esc` `Ctrl+[` | Normal モードへ |

Normal モードと Visual モードでは、割り当てのないキーはバッファに入力されず破棄されます。

### モーション

`h` `j` `k` `l` `w` `W` `b` `B` `e` `E` `0` `^` `$` `gg` `G` `{` `}` `%` `f{char}` `F{char}` `t{char}` `T{char}`
`` `{mark} `` `'{mark}`

いずれもカウント接頭辞を取ります（`3w`、`5j`、`2f,` など）。`G` はカウントで行番号指定になります。

`%` は対応する括弧へ移動します。カーソルが括弧の上になければ、その行を右に見ていって最初の
括弧を使います。対象は Vim の既定と同じ `()` `[]` `{}` の3種です。inclusive なモーションなので、
`d%` は括弧を含めて消します（モーションはカーソルから働くので、括弧の手前から打つとそこまでが
範囲に入ります）。

### オペレータ

`d` `c` `y` `>` `<` を上記のモーションと自由に組み合わせられます（`dw` `d$` `c3w` `y}` `dfx` `>j` など）。
オペレータを重ねると行単位になります（`dd` `cc` `yy` `>>` `<<`）。カウントは前後どちらにも置け、
両方あれば掛け算されます（`2d3w` は6単語削除）。

短縮形として `D`（`d$`）、`C`（`c$`）、`Y`（`yy`）、`S`（`cc`）、`x` `X` `s` があります。

`>` `<` は行の字下げです。Vim と同じくモーションが文字単位でも行に作用し（`>w` は単語ではなく
その行を下げます）、Visual モードではカウントが段数になります（`3>` で3段）。下げ幅とタブ・
スペースの別は VS Code の設定に従います。字下げ自体を `editor.action.indentLines` に
委ねているため、言語ごとの設定もそのまま効きます。

### テキストオブジェクト

`iw` `aw` `iW` `aW`、括弧の `i(` `a(` `i[` `a[` `i{` `a{` `i<` `a<`（`ib` `ab` `iB` `aB` も可）、
引用符の `i"` `a"` `i'` `a'` `` i` `` `` a` ``。オペレータの後（`ciw`）でも Visual モード中
（`viw`）でも同じように使えます。

### マーク

- `m{a-z}` で現在位置を覚え、`` `{a-z} `` でその位置へ、`'{a-z}` でその行の先頭非空白へ戻ります。
- どちらもモーションなので、オペレータと組み合わせられます。`` d`a `` は文字単位、`d'a` は行単位です。
- `G` `gg` `{` `}` `%` `/` `n` のような大きな移動は戻り先を覚えます。`` `` `` で直前の位置へ、
  `''` でその行へ戻れます。`h` `j` `k` `l` のような小さな移動は戻り先を書き換えません。
- マークはファイルごとに別々です。ファイルをまたぐマーク（大文字 `A-Z`）は未対応です。
- マークを付けた行は、行番号の横にマーク名が出ます（`vimLike.showMarks` で消せます）。
  出るのは `m` で付けた名前付きマークだけです。`` `` `` の戻り先は移動のたびに変わるため出しません。
- `:marks` で一覧が出ます。マーク名・行番号・その行の中身が並び、選ぶとその位置へ移動します。
  ガターと違い、こちらには `` `` `` の戻り先も載ります。どこから飛んできたかは一覧では有用だからです。
- `:delmarks a`、`:delmarks a b`、`:delmarks ab`、`:delmarks a-d` で消せます。
  `:delmarks!` は名前付きマークをすべて消します。Vim と同じく `:delmarks` は引数が必須です。
  `` `` `` の戻り先は `:delmarks!` でも残ります。移動のたびに付け直されるもので、消しても
  すぐ元に戻るからです。

### レジスタとその他

- `"a` などで名前付きレジスタを指定します（`"ayy` `"ap`）。大文字は追記です。
- `p` `P` で貼り付け。行単位のレジスタは行として、文字単位のレジスタは文字として貼られます。
- `r{char}` 置換、`~` 大小反転、`J` 行連結、`u` / `Ctrl+r` で取り消し・やり直し。
- `.` で直前の**変更**を繰り返します。カーソル移動やヤンクは変更ではないので、間に挟んでも
  繰り返す対象は変わりません（`cw` で直して `n.` `n.` と進む使い方ができます）。Insert モードを
  通った変更では、打った内容ごと繰り返します。`3.` は Vim と同じくカウントの置き換えで、
  「3回繰り返す」ではなく「元のコマンドをカウント3で実行し直す」意味です。

### コマンドライン（`:`）

`:` でコマンドラインモードに入ります。打った内容はステータスバーに `:w` のように出て、
フォーカスはエディターに残ります。`Enter` で実行、`Esc` で取り消し、`Backspace` で1文字削除
（`:` まで消すとモードを抜けます）。

| コマンド | 動作 |
| --- | --- |
| `:w` | 保存 |
| `:q` / `:q!` | 閉じる / 変更を捨てて閉じる |
| `:qa` / `:qa!` | すべて閉じる |
| `:wqa` `:xa` | すべて保存して閉じる |
| `:wq` `:x` | 保存して閉じる |
| `:sp` / `:vs` | 上下 / 左右に分割 |
| `:tabnew` | 新しいファイル |
| `:42` / `:$` | その行 / 最終行へ |
| `:marks` | マークの一覧。選ぶとその位置へ移動します |
| `:delmarks {名前}` | 指定したマークを消す（`a`、`a b`、`ab`、`a-d`） |
| `:delmarks!` | 名前付きマークをすべて消す |

`:write` `:split` `:vsplit` のように省略しない綴りでも書けます。範囲指定や引数は解釈しないので、
`:w foo` や `:%s/a/b/` は `E492: Not an editor command` として知らせます。黙って別のことを
するよりは、できないと言うほうを選んでいます。唯一の例外が `:delmarks` で、こちらはマーク名を
引数に取ります（詳しくは[マーク](#マーク)を参照）。

保存の手段が `:w` だけというわけではありません。キー割り当てから VS Code のコマンドを直接
呼べるので、`{ "before": ["<leader>", "s"], "commands": ["workbench.action.files.save"] }` でも
同じです。init.vim の書き方に寄せたい場合は `{ "after": [":", "w", "<CR>"] }` と書けます。

### 検索（`/` `?` `n` `N` `*` `#`）

`/` で前方、`?` で後方に検索します。入力欄は `:` と同じくステータスバーで、`Enter` で確定、
`Esc` で取り消しです。確定するまでカーソルは動きません。

| キー | 動作 |
| --- | --- |
| `/pattern` `?pattern` | 前方 / 後方へ検索 |
| `n` `N` | 同じ向き / 逆向きに繰り返し |
| `*` `#` | カーソル下の単語を前方 / 後方へ検索 |
| `/` `?` を空のまま確定 | 直前のパターンをもう一度 |

バッファの端まで行くと反対側へ回り込みます（Vim の `wrapscan` 相当）。カウントは何個目の一致かを
指し（`3n`）、`d/foo<CR>` `dn` `v/foo<CR>` のようにオペレータや Visual モードとも組み合わせられます。

`n` の向きは**最後に打った `/` か `?` で決まります**。`?foo` のあとの `n` は後方へ続き、`N` が
前方へ戻ります。`*` `#` も同じく、直前の検索としてパターンを残します。

#### パターンは JavaScript の正規表現

Vim の方言（`\v` `\<` `\{-}`）は解釈しません。中途半端に翻訳すると、意図と違うものに黙って
一致するほうが厄介だからです。よく使うものの対応は次のとおりです。

| Vim | この拡張機能 |
| --- | --- |
| `\<foo\>` | `\bfoo\b` |
| `\d` `\s` | `\d` `\s`（同じ） |
| `\{-}`（最短一致） | `*?` `+?` |
| `\(...\)` | `(...)` |
| `\|` | `\|`（グループ内では `|`） |

大文字小文字は常に区別します（`ignorecase` 相当の設定はありません）。見つからないときや壊れた
パターンのときは、Vim と同じ文言（`E486: Pattern not found` など）をステータスバーに出します。

#### VS Code の検索バーに切り替える

`vimLike.search` を `editorFind` にすると、`/` が VS Code の検索バー（`actions.find`）を開きます。
どちらが手に合うかは好みなので、設定ひとつで行き来できるようにしてあります。

```jsonc
"vimLike.search": "editorFind"   // 既定は "statusBar"
```

| | `statusBar`（既定） | `editorFind` |
| --- | --- | --- |
| 入力欄 | ステータスバーに `/foo` | VS Code の検索バー |
| パターン | JavaScript の正規表現で固定 | リテラル / 正規表現をトグル |
| 大文字小文字・単語単位 | 常に区別 / `*` `#` のみ単語単位 | 検索バーのトグルで切り替え |
| 件数・履歴・ハイライト | なし | あり（「1/8」の表示、履歴、全一致の強調） |
| `n` `N` | モーション。`3n` も `dn` も効く | コマンド。`3n` は効くが `dn` は不可 |
| `d/foo<CR>` `v/foo<CR>` | 効く | 不可（打鍵が検索バーへ行くため） |

`editorFind` でも `*` `#` は使えます。カーソル下の単語を選択してから「選択範囲を検索」に渡す
作りです。VS Code の検索は選択文字列をそのまま探すので、`\b` で囲む既定の `*` と違い、`foo` は
`foobar` にも止まります。一致へ移ったあとはカーソルを一致の先頭へ置き直しています。VS Code の
検索は一致を選択状態にするため、そのままだと Normal モードなのに選択が残るからです。

### ウィンドウ操作

`Ctrl+W` に続けて `h` `j` `k` `l` でエディターグループ間を移動、`s` `v` で分割、`c` で閉じます。

サイドバーやパネルの表示切替は VS Code 標準のキー（`Ctrl+B` など）をそのまま使います。
この拡張機能では再定義していません。

## 設定

設定画面で `Vim Like` を検索してください。

- `vimLike.enabled`: Vim モードの有効・無効（既定値: `true`）。ステータスバーの表示をクリックしても切り替わります。
- `vimLike.startInNormalMode`: エディターを切り替えたときに Normal モードへ戻すか（既定値: `true`）
- `vimLike.showModeInStatusBar`: ステータスバーに現在のモードを表示するか（既定値: `true`）
- `vimLike.showMarks`: マークを付けた行の行番号の横にマーク名を表示するか（既定値: `true`）
- `vimLike.leader`: キー割り当ての `<leader>` が指すキー（既定値: スペース）

### キーの割り当てを変える

`vimLike.normalModeKeyBindings` と `vimLike.visualModeKeyBindings` で、キーを別のキー列に
置き換えられます。Vim の `nnoremap` / `vnoremap` に相当します。

```jsonc
"vimLike.normalModeKeyBindings": [
  { "before": ["H"], "after": ["^"] },
  { "before": ["J"], "after": ["1", "0", "j"] },
  { "before": ["K"], "after": ["1", "0", "k"] },
  { "before": ["L"], "after": ["$"] },
  { "before": ["U"], "after": ["<C-r>"] },

  { "before": ["<leader>", "n"], "commands": ["workbench.view.explorer"] },
  { "before": ["<leader>", "h"], "commands": ["workbench.action.navigateLeft"] },
  { "before": ["<leader>", "w", "h"], "commands": ["workbench.action.decreaseViewWidth"] }
]
```

- `before` と `after` は 1 要素が 1 キーです。`10j` は `["1", "0", "j"]` と書きます。
- `after` の代わりに `commands` を書くと、VS Code のコマンドを直接呼べます。
- `<Esc>` `<C-r>` `<Space>` `<leader>` が特殊キーとして使えます。
  `<leader>` が何を指すかは `vimLike.leader` で変えられます（既定値はスペース）。
- 置き換えた結果はさらに置き換えられません（`nnoremap` と同じく非再帰です）。
- `f` `t` `r` `m` `` ` `` `'` の引数と、`"` に続くレジスタ名は置き換えの対象外です。
  `J` を割り当てていても `fJ` は文字 `J` を探し、`` `J `` は名前 `J` のマークを指します。
- 複数キーの `before` は、より長い規則が一致しうるあいだ次のキーを待ちます。
  `["g", "w"]` と `["g", "w", "h"]` を両方定義すると、短いほうは発火しません。
  待機中はステータスバーに打鍵済みのキーが出ます（スペースは `␣` と表示されます）。
- Vim の `timeoutlen` にあたる打ち切りはありません。待っているあいだは表示で分かるので、
  手が止まっただけで打鍵が実行されるより確実だと考えています。

すぐ使える設定例を [examples/settings.jsonc](examples/settings.jsonc) に置いています。
`H` `J` `K` `L` の置き換えから leader 起点のウィンドウ操作まで一式入っているので、
settings.json に貼り付けてから削っていくのが早いと思います。

### エクスプローラーとターミナル

**エクスプローラーではモードやオペレータは使えません。** ツリービューであってテキスト
エディターではないため、打鍵が `type` コマンドを通らないからです。ただし `j` `k` `h` `l`
での移動なら、VS Code の `list.*` コマンドをキーに割り当てることで実現できます。
例を [examples/keybindings.jsonc](examples/keybindings.jsonc) に置いています
（settings.json ではなく keybindings.json に書きます）。

**ターミナルでは何もできません。** 打鍵が疑似端末へ直接渡されるため、VS Code の拡張機能
からは手が出せません。行編集を Vim 風にしたい場合は、シェル側で `set -o vi`（bash）や
`bindkey -v`（zsh）を設定してください。

なおこの拡張機能は、エクスプローラーやターミナルにフォーカスがあるときにキーを奪いません。
すべてのキーバインドに `editorTextFocus` を付けており、構造テストで強制しています。

## 制限

- 既定の検索には結果のハイライト（`hlsearch`）と入力中の追従（`incsearch`）がありません。カーソルが
  移動するだけです。どちらも欲しい場合は `vimLike.search` を `editorFind` にすると VS Code の
  検索バーが担いますが、代わりにオペレータとの組み合わせ（`d/foo`）ができなくなります。
- 検索パターンは JavaScript の正規表現で、Vim の方言は解釈しません。
- Ex コマンドは決め打ちの一覧のみです。範囲指定や置換（`:%s/foo/bar/`）、引数（`:w foo`）は
  未対応です（例外は `:delmarks` のマーク名だけ）。
- `:qa!` は `:qa` と同じ動きで、未保存のファイルがあれば VS Code が確認を出します。
  すべてのエディターの変更を破棄して閉じるコマンドが VS Code に存在しないためです。
  1つ分の `:q!` は破棄できます。
- マクロは未対応です。
- マークは編集に追従しません。マークを付けたあとに上の行を消すと、マークは行番号のまま残るため
  指す場所がずれます。追従させるには文書の変更を購読して位置を補正する必要があり、まだ入れていません。
- `{count}%`（ファイルの何割の位置へ飛ぶ Vim の機能）は未対応です。`%` は括弧の対応のみです。
- `%` は `matchit` が足す `if`/`endif` や HTML タグの対応までは見ません。
- `.` は Insert 中にマウスや矢印キーでカーソルを動かすと、打った内容を記録できません。
  その場合は変更の構造だけ（`cw` なら単語の削除まで）を繰り返します。
- `u` と `Ctrl+r` は VS Code の取り消し履歴に委譲しているため、取り消しの粒度は Vim と一致しません。
- モードはウィンドウ全体で1つです。エディターごとに別々のモードは持ちません。
