# デモの手順

人前でこの拡張機能を動かすときの台本です。所要はおよそ10分、技術者向けの幕7を足して12分です。

打鍵と結果はすべて実物のエンジンに通して確かめてあります。ここに書いてある「こう打つとこうなる」は、
書き手の記憶ではなく実行結果です。

## 事前準備

### かならず確認すること

**IME を切る。** ここが最大の落とし穴です。Normal モードでは IME を有効にしたままコマンドが打てません。
変換中の `d` とコマンドの `d` を区別する手立てがなく、OS の IME を拡張機能から切ることもできないためです。
日本語環境のデモでは確実に踏みます。

**他の Vim 系拡張を個別に無効化する。** `type` コマンドはウィンドウ全体で1つしか登録できないので、
`asvetliakov.vscode-neovim` や `vscodevim.vim` が有効だと起動時にエラーになります。

```sh
code --disable-extension=asvetliakov.vscode-neovim --disable-extension=vscodevim.vim
```

`--disable-extensions` で全部止めてはいけません。デモに使う Git Graph や AI パネルまで消えます。

**スクリーンキャストモードを入れる。** コマンドパレットから **Developer: Toggle Screencast Mode** です。
打鍵が画面に出ます。Vim のデモは「何を押したか」が見えないと何も伝わらないので、これが一番効きます。

### 見栄えの準備

- フォントを拡大する（**View: Zoom In** を数回）
- ミニマップを消す（`editor.minimap.enabled` を `false`）
- `examples/settings.json` と `examples/keybindings.json` の中身を反映しておく

### 幕5（ターミナル）を見せる場合

出力の取り込みには VS Code のシェル統合が要ります。`echo $VSCODE_SHELL_INTEGRATION` が空なら効いていません。
`.zshrc` で `kiro-cli` などがシェルを `exec` で置き換えていると無効になるので、settings.json に次を足します。

```jsonc
"terminal.integrated.env.osx": { "PROCESS_LAUNCHED_BY_Q": "1" }
```

### サンプルファイル

幕2から幕4で使います。`demo.txt` として保存してください。保存済みのファイルであることが必要です。

```text
hello world
one two three four
one two three four five six
call(alpha, beta)
const name = "x"
alpha
beta
aa bb aa bb
one one one
    indented text
```

## 幕1 — モードが本物であること（1分）

作り直した理由そのものなので、最初に置きます。1行目の行頭にカーソルを置いて始めます。

| 打鍵 | 起きること |
| --- | --- |
| `qqq` | **何も起きない。`q` はバッファに入らない** |
| `xxx` | `hello world` が `lo world` になる |
| `u` | 戻る |

言うこと。

> 最初の実装では、いまの `q` がそのままファイルに入っていました。割り当てのないキーが素通りしていたので、
> Normal モードがモードとして成立していなかったんです。いまは、割り当てのあるキーはコマンドとして働き、
> 割り当てのないキーは捨てられます。どちらの場合も文字は挿入されません。

`q` を選んでいるのは、本当にどこにも割り当てがないからです。`z` `Q` `Z` も同じです。
`H` `K` `L` `M` `R` `U` は Vim にはありますがこの拡張が未実装なだけ、`Y` `p` `n` は静かに効くだけなので、
この幕には使えません。

## 幕2 — 文法が直交していること（2分）

一覧を見せるのではなく、掛け算になっていることを見せます。

2行目 `one two three four` の行頭で。

| 打鍵 | 結果 |
| --- | --- |
| `dw` | `two three four` |
| `de` | ` two three four` |
| `d2w` | `three four` |
| `d$` | 空行になる |

3行目 `one two three four five six` の行頭で。

| 打鍵 | 結果 |
| --- | --- |
| `2d3w` | 空行になる（6単語） |

言うこと。

> `dw` は単語の手前で止まり、`de` は最後の文字まで消します。この違いを持っているのはモーション側で、
> オペレータは知りません。だから「オペレータ数 × モーション数」ではなく「オペレータ数 + モーション数」で
> 済んでいて、モーションを1つ足すと全オペレータから使えるようになります。

そのままテキストオブジェクトへ。4行目 `call(alpha, beta)` の `alpha` の上、5行目 `const name = "x"` の
`name` の上で。

| 打鍵 | 結果 |
| --- | --- |
| `di(` | `call()` |
| `ciw` | `const  = "x"` に変わって Insert モードへ |
| `gUiw` | 単語が大文字になる |

6行目と7行目の `alpha` / `beta` で、レジスタを見せます。

| 打鍵 | 結果 |
| --- | --- |
| `yyp` | `alpha` が複製される |
| `"ayy` `j` `"ap` | 名前付きレジスタ `a` 経由で貼る |

## 幕3 — 検索がモーションであること（1分）

他の拡張との差が一番はっきり出るところです。2行目 `one two three four` の行頭で。

| 打鍵 | 結果 |
| --- | --- |
| `d/three<CR>` | `three four` |

8行目 `aa bb aa bb` の行頭で。

| 打鍵 | 結果 |
| --- | --- |
| `d2/bb<CR>` | `bb`（2つ目の一致まで消える） |

言うこと。

> 検索を VS Code の検索バーに渡す作りにすると、打鍵が検索バーへ行ってしまうので、オペレータと
> 組み合わせられません。だから `/` は自前で持っています。VS Code の検索バーは履歴も一致件数もあって
> 便利なので、`<leader>/` に別に置いてあります。どちらかを設定で選ばせるのではなく、両方あります。

続けて `.` の繰り返し。9行目 `one one one` の行頭で。

| 打鍵 | 結果 |
| --- | --- |
| `cw` `two` `<Esc>` `w` `w` `.` | `two one two` |

Insert モードを通った変更は、打った内容ごと繰り返されます。

## 幕4 — マーク（1分）

VS Code ならではの見た目があるので映えます。6行目 `alpha` で。

| 打鍵 | 起きること |
| --- | --- |
| `ma` | 行番号の横に `a` のアイコンが出る |
| `j` `j` | 離れる |
| `` `a `` | 戻る |
| ``d`a`` | マークまで削除（モーションなのでオペレータと組める） |
| `:marks` | 一覧が出る。選ぶとその位置へ飛ぶ |

`:marks` の一覧には `` ` ``（直前の位置）も載ります。ガターには出しません。移動のたびに変わるものなので、
常時表示すると邪魔になるためです。

## 幕5 — ターミナルが文書になる（2分）

一番新しく、一番説明が要る機能なので、ここを山にします。

| 打鍵 | 起きること |
| --- | --- |
| `<leader>t` | ターミナル用の作業バッファが開く |
| `npm test` と書いて `<leader>r` | ターミナルで実行され、出力が同じバッファに追記される |
| `/fail<CR>` | 出力の中を検索して飛ぶ |
| `ciw` で書き換えて `<leader>r` | 直したコマンドを送り直す |
| `<leader>R` | 送り先のターミナルを選ぶ |

`<leader>R` の一覧には、検出されたシェルとシェル統合の有無が並びます。統合のない相手に送ると
コマンドは動くのに出力だけ取り込めないので、選ぶ時点で見えるようにしてあります。

言うこと。

> ターミナルの中に Vim を作ったのではなく、ターミナルの仕事を Vim が扱える場所へ持ってきました。
> 文書なので、モーションも検索もマークも1つも実装し直していません。

## 幕6 — init.vim がそのまま乗ること（1分）

10行目 `    indented text` の行末あたりで。

| 打鍵 | 結果 |
| --- | --- |
| `H` | 行頭の非空白へ（`^` に置き換えてある） |
| `L` | 行末へ（`$` に置き換えてある） |
| `J` | 10行下へ |
| `<leader>n` | ファイルツリーの開閉 |
| `:gg` | Git Graph が開く |
| `:qa` | すべて閉じて、ファイルツリーに着地する |

言うこと。

> 拡張機能の既定は素の Vim のままにしてあります。`H` を `^` にするような個人の調整は設定側の
> リマップでやるので、dotfiles として持ち運べます。`:gg` のような他の拡張機能のコマンドも設定側です。
> 同梱していないツールのコマンド ID を、この拡張機能が知っているべきではないからです。
>
> `:qa` は Vim ならセッションごと終わりますが、ここではウィンドウが残ります。タブが全部消えると
> 打ち込む先も動かす先もなくなるので、ファイルツリーに着地させています。Vim に似せるより、
> VS Code で行き詰まらせないほうを採った箇所です。

## 幕7 — 作りの話（技術者向け・2分）

聞き手が技術者のときだけ。ここを主役にするなら幕2を短くします。

- `src/core/` は `vscode` を1行も import しない。それをテストで強制している
- 373件のテストが VS Code を起動せずに1秒未満で走る
- 期待値を推測で書かず、実物の Vim で実測している。`guu` は先頭の非空白へ、`Vu` は列0へ、という
  食い違いもそれで見つかった
- テストが空回りしていないかを、実装をわざと壊して確かめている

`npm test` をその場で走らせると速さが伝わります。

## 落ちやすいところ

| 症状 | 原因 |
| --- | --- |
| 打った文字がバッファに入る | IME が有効になっている |
| 起動時にエラーが出る | 他の Vim 系拡張が `type` を先に取っている |
| `<leader>r` の出力が出ない | シェル統合が無効。`<leader>R` の一覧で確認できる |
| `<leader>e` が「保存していないファイル」と言う | 参照を送る機能なので、名前のないファイルは対象外 |

## 削ることを勧めるもの

`<leader>e`（AI パネルへ参照を送る）と `<leader>E`（送り先の選択）は、外部拡張の状態に依存するので
生放送では落ちやすいところです。時間が余ったときの予備にしてください。
